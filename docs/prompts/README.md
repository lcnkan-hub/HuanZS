# 需求规格（给 AI 编码代理的施工图）

这里存放本项目各里程碑的**需求规格文档**。写法是把一个模糊想法，写成 AI 编码代理能独立执行的施工图。

## 本项目的工作方式

分工是固定的：

| 环节 | 谁负责 |
|---|---|
| 产品定义 · 需求拆解 | 我 |
| 架构决策 · 技术选型 | 我 |
| 验收标准 · 完成判据 | 我 |
| 编码实现 | AI 编码代理（Claude Code / Codex） |
| 代码审查 · 跑验收 | 我 |

所以每一份文档，都是一次「把需求变成可验收任务」的完整练习：要写清角色、边界、禁止项和完成判据，代理才有可能一次做对。**这和"让 AI 写代码"不是一回事**——差别全在文档里那几条不写就会做错的约束。

## 文档清单

| 编号 | 内容 | 关键约束 |
|---|---|---|
| M19 | 记忆模块 v3 | 记忆白名单四类 + 注入时机 |

| M23 | 数据导出补全 / 导入 / 回退 | 完成标准是「丢得起」，不是「不丢」 |

## 说明

- 早期标题里的「发 Claude Code」指的是当时执行任务的编码代理，不等于这些文档只对某一个工具有效——它们描述的是需求本身。
- 相关产品规则见根目录 `RULES.md` 的「产品宪法」一节。
