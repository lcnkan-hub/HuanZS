## 1 · 三件各自怎么做

### ① I15 存储满了：从「假成功」改成「如实报 + 常驻可见 + 给出口」

**现状**（`useLocalStorage.js:73-88`）：`setItem` 抛错 → 弹一句 alert → 继续跑。
**口径修正**：`localStorage.setItem` 是**原子**的，严格说不会「写半损」。真实的问题是**假成功**——内存里的值还在、界面看着一切正常，刷新就没了，而且用户不知道从哪一刻开始丢的。所以修的不是 setItem，是**报账与可见性**。

**做法**
- 新增 `utils/storageHealth.js`（模块级单例）：记「哪个键写失败、何时、什么原因」+ 容量体检（逐键字节数 + 总量/上限）
- `useLocalStorage` 写失败 → **记账**（键、人话标签、原因），同一键只留一条（不刷屏）；alert 只弹一次；后续同键写**成功** → 清掉该条记录
- 新增 `components/common/NoticeBar.vue` 常驻条，说清三件事：
  - 哪一份数据没存上（人话：「王冠记忆」「百科条目」，不是 `huan_zhong_shu_memory_v1@u3f2a`）
  - 本机已用多少（例：`4.8 MB / 约 5 MB`）
  - 两个出口按钮：**「导出备份」** · **「清一清没被引用的图片」**（复用已有的 `purgeUnusedImages`，它带双闸门）
- 提示条**不可永久关闭**，只能暂时收起——这一条是根：能被忽略一次就消失的提醒等于没有

**边界**：不做预防性拦截（提前估算体积再拦写入会误伤正常保存；`setItem` 自己会失败，我们只负责如实报）

### ② I14 导出提醒：从「有个按钮」变成「真做过」

**现状**：能力已有（I01），但只有「我的 → 备份中心」卡片里一行小字（`BackupCenter.vue:21-22`），没有任何主动提醒。用户不点 = 等于没有。

**做法**
- 新增 `utils/backupReminder.js`：**纯判据** `shouldRemind({ lastExportAt, now, snoozedUntil, hasData })`（可脱界面单测，同 `proactiveJudge.js` 的写法）
  - **从没导出过 → 不提醒**（新装就被催很烦；卡片里那行小字已经说了）
  - 距上次导出 **≥ 14 天** → 提醒
  - **本机没数据（空库）→ 不提醒**
  - 点「今天先不提醒」→ snooze 只到**次日 0 点**（压一天，不永久消失）
- 触发点：`App.vue` onMounted 判一次 —— 与王冠主动开口同款时机（纯前端只有「打开 app 那一刻」；I05 天花板，写进边界）
- 载体：复用 `NoticeBar`，优先级**低于**「写失败」（两条撞车时先报写失败）
- `BackupCenter` 那两行接到**同一套判据、同一份数据**上（不重复算，文案统一）

### ③ A07 多标签页互相覆盖

**现状**：全库 grep 无 `addEventListener('storage')` 命中；各 composable 的模块级 `ref` 各持一份快照，后写静默覆盖先写。

**做法**
- 新增 `utils/storageSync.js`：模块级单例，**只注册一次** `window.addEventListener('storage')`，按真实键派发订阅者；node / 无 `window` 环境自动降级为空实现
- `useLocalStorage` 订阅自己的真实键：收到事件 → 经「应用远端值」闸门写入 `data.value`（`watch` 看见闸门就不回写，避免 A↔B 乒乓写）；`newValue === null` → 回落默认值
- 键名**精确匹配**（含 `@u<账号id>` 后缀）——别的账号的键即使 base 同名也**不响应**（否则破账号隔离）
- v1 **不做 toast**：本批目标只是「不再静默丢」。谁改的、什么时候的可视化留给 P3 体验打磨

**已知不覆盖（写进 done_note）**
- IndexedDB 图片库**没有 storage 事件**：两标签页同时动图片仍可能互相覆盖（图片以增删为主 + A02 回收有双闸门，风险低）→ backlog
- 同一条**同时改**仍是「后写覆盖先写」：本批只保证**不再静默**（值会同步过来），不做合并/冲突选择 → backlog
