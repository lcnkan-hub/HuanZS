# 新功能接入指南 · 架构接缝清单

> 写于 2026-11-24 存储层收口之后。目的只有一个：**加新东西时知道该插在哪，不用先读懂全项目。**
> 每条都写了「改哪」「漏了会怎样」——第二种比第一种重要，因为漏掉的坑通常是静默的。

## 分层与方向（硬约束）

```
constants/   纯数据表（键名、导航、图标、阈值）—— 不 import 任何东西
utils/       纯函数 —— 不 import vue、不 import composables/services
services/    无界面能力（存储适配、危机管线、端口）—— 不 import composables
composables/ Vue 状态与业务编排 —— 可以 import 上面三层
components/  界面 —— 取状态走 composables / props，不直接摸存储
```

违反方向的症状：node 里跑不起来（要先备 DOM/IndexedDB 替身）、循环依赖、换个实现要动一片。
`useChatAI → crisisResponse → crisisDetection → useChatAI` 那个环就是这么长出来的（已用 `services/aiClassifierPort` 断开）。

---

## 1. 加一个存储键

改三处，全在 `src/constants/storage.js` + `src/utils/storageScope.js`：

| 动作 | 位置 | 漏了会怎样 |
|---|---|---|
| 登记键名 | `STORAGE_KEYS.XXX` | — |
| 写人话标签 | `KEY_LABELS[STORAGE_KEYS.XXX]` | 写失败提示条只能念 `huan_zhong_shu_xxx@u3f2a` |
| 归类 | 账号数据进 `SCOPED_BASE_KEYS`；设备级进 `GLOBAL_KEYS` | 首个账号认领不到旧数据 / 账号之间串数据 |

读写一律走 `services/storageAdapter`：

```js
import { readJSON, writeJSON } from '../services/storageAdapter'        // 账号隔离 + JSON
import { readRaw, writeRaw } from '../services/storageAdapter'          // 不加前缀、不解析
import { readRawScoped } from '../services/storageAdapter'              // 加前缀但「坏数据」要能分辨
import { tryWriteJSON } from '../services/storageAdapter'               // 写失败要能告诉用户
```

**不要**再写 `localStorage.getItem(...)`（业务层已清零，2026-11-24）。

## 2. 让新数据跟着备份走

改 `src/composables/useBackup.js` 的 `TEXT_SOURCES`，一行：

```js
{ path: ['你的字段名'], key: () => STORAGE_KEYS.YOUR_KEY, empty: null }
```

漏了会怎样：导出/导入不报错，但**换设备后这份数据静默消失**。
危机类数据要进 `CRISIS_SOURCES`；二进制（图片之类）走 IndexedDB 分支，不进这张表。

## 3. 加一种 AI 能力

- 一次性结构化提问（抽取、分类、打分）：直接用 `askStructured(systemPrompt, userContent)`（`composables/useChatAI.js`）。
- 需要被 **services 层消费**的 AI 能力（像危机检测的 L2）：注册到 `services/aiClassifierPort.js`。
  注意它目前只有一个槽位 —— 要同时挂多种能力时，把它扩成 `Map<name, fn>`，别再加第二个全局变量。
- 会真的发网络请求的地方，必须：超时（`REQUEST_TIMEOUT`）+ 无 key 时返回 null + 上层不得假装成功。

## 4. 加一个页面 / 一个业务领域

```
src/components/<domain>/     界面（PascalCase.vue）
src/composables/use<Domain>.js   该领域的状态与读写
```

- 页面切换：`composables/usePageRouter.js`（`activeView` / `pageClass` 负责进出动画状态机）
- 挂载点：`App.vue` 模板里加一层，**别动** `.sheet-body` 上的 `:key` / `v-if`（AGENTS.md 三条禁令）
- 需要跟底栏共存：底栏在 `App.vue` 是一次性渲染的；新页面若是「叠层」而不是「换 Tab」，参考详情页的 `pageClass` 用法

## 5. 加一个 Tab

改 `constants/categories.js` 的 `NAV_ITEMS`（`TAB_IDS` 自动派生），图标 key 同步登记 `constants/icons.js` 的 `ICON_MAP`。
漏了图标 → AppIcon 渲染空白，不报错。

## 6. 换存储后端（IndexedDB / SQLite / 云端）

只改 `src/services/storageAdapter.js`。它对外暴露的下面这些能力要一起保持语义：

```
readJSON / writeJSON          账号隔离 + JSON + 失败落内存
readRaw  / writeRaw           不加前缀、不解析（给全局键、拼接键）
readRawScoped                 「键不存在」与「数据坏了」必须能区分
listKeys                      枚举（备份、跨账号回收图片）
tryWriteJSON / tryWriteRaw    写失败返回 false，绝不落内存兜底
resolveKey                    键 → 实际键
```

换后端时**不要**顺手改 `useLocalStorage`（Vue 外壳）和 `utils/storageScope`（键名规则）—— 它们是上层语义，动了会连带改一堆调用方。

## 7. 换图片来源

`utils/markdownParser.resolveImagesAsync(html, resolveImage)` 是注入点：
调用方（现在是 `ItemBodyEditor`）决定 `id → url` 怎么取。想改成云端 CDN，只换这个函数的实现。
**不要**再把图片库 import 回 `utils/`。

## 8. 加可观测性（失败可见）

- 写失败记账：`composables/useStorageHealth.js` 的 `reportWriteFailure / clearWriteFailure`
- 界面呈现：`App.vue` 的 `notice` 计算属性 + `components/common/NoticeBar.vue`
- 原则（I15）：写失败**不许静默**——记账 + 提示条常驻，直到真的写成功。
